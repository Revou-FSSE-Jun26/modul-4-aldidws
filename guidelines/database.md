# Database Engineering Guidelines — RevoTask

Five rules that were enforced or violated during RevoTask development.

---

## UUID Primary Keys

### Rule
Every core domain entity table (users, boards, board_columns, cards, comments, notifications) MUST use a UUID primary key generated by `uuid.uuid4`. UUID columns MUST use a UUID-compatible SQLAlchemy type. Foreign-key columns referencing UUID primary keys MUST use a compatible type.

### Rationale
UUID primary keys prevent sequential ID enumeration attacks, allow distributed ID generation without a database round-trip, and ensure that IDs do not leak record counts to clients. Using incompatible types between primary key and foreign key columns causes SQLAlchemy relationship errors.

### RevoTask Example
```python
import uuid
from sqlalchemy import Uuid
from sqlalchemy.orm import mapped_column, Mapped

class Card(db.Model):
    __tablename__ = "cards"

    id: Mapped[uuid.UUID] = mapped_column(
        Uuid(as_uuid=True),
        primary_key=True,
        default=uuid.uuid4,
    )

    # Foreign key — same type as the referenced primary key
    column_id: Mapped[uuid.UUID] = mapped_column(
        Uuid(as_uuid=True),
        db.ForeignKey("board_columns.id", ondelete="CASCADE"),
        nullable=False,
        index=True,
    )
```

## Float for Card Ordering

### Rule
Card ordering MUST use a `Float` column named `order`. The column MUST have a non-negative check constraint and a composite index on `(column_id, order)`. All service layer references MUST use the name `order`, not `position`.

### Rationale
Integer position columns require renumbering every card at or after the insertion point whenever a card is inserted between two existing cards. Float ordering allows midpoint insertion (`1.5` between `1.0` and `2.0`) with zero additional writes to other rows, making drag-and-drop reordering efficient at any list size.

### RevoTask Example
```python
class Card(db.Model):
    __tablename__ = "cards"

    # WRONG (original AI output)
    # position: Mapped[int] = mapped_column(Integer, nullable=False, default=0)

    # CORRECT
    order: Mapped[float] = mapped_column(Float, nullable=False, default=0.0)

    __table_args__ = (
        CheckConstraint('"order" >= 0', name="ck_cards_order_nonnegative"),
        Index("ix_cards_column_id_order", "column_id", "order"),
    )
```

## Soft Delete with deleted_at

### Rule
Entities that users may restore or that must remain available for audit MUST include a `deleted_at` nullable timestamp column. Ordinary application queries MUST filter `deleted_at IS NULL` by default. Restoration sets `deleted_at = None`. Soft delete MUST NOT be automatically applied to every model — only to entities with a defined restoration or retention requirement.

### Rationale
Hard-deleting a record is irreversible. For boards and cards, users expect an undo capability. Soft delete provides this without complex event sourcing. Applying `deleted_at` to every table, including association and audit tables, adds unnecessary overhead and complicates unique constraint design.

### RevoTask Example
```python
from datetime import timezone

class Card(db.Model):
    __tablename__ = "cards"

    deleted_at: Mapped[datetime | None] = mapped_column(
        DateTime(timezone=True),
        nullable=True,
        default=None,
    )

# Service — query must exclude soft-deleted records
def list_cards(column_id: uuid.UUID) -> list[Card]:
    return (
        Card.query
        .filter(Card.column_id == column_id, Card.deleted_at.is_(None))
        .order_by(Card.order)
        .all()
    )

# Restoration
def restore_card(card: Card) -> Card:
    card.deleted_at = None
    db.session.commit()
    return card
```

## snake_case Table and Column Naming

### Rule
Table names MUST use plural `snake_case` (e.g. `board_columns`, not `BoardColumn` or `boardcolumns`). Column names MUST use `snake_case`. Foreign-key columns MUST end with `_id`. Constraint names MUST follow the pattern `pk_<table>`, `fk_<table>_<col>_<ref>`, `uq_<table>_<col>`, `ix_<table>_<col>`, `ck_<table>_<desc>`.

### Rationale
Consistent naming makes migrations readable and prevents accidental collisions with SQL reserved words. Explicit constraint names make it possible to reference and drop constraints in future migrations without guessing Alembic-generated names.

### RevoTask Example
```python
class BoardColumn(db.Model):
    __tablename__ = "board_columns"   # plural snake_case

    id: Mapped[uuid.UUID] = mapped_column(Uuid(as_uuid=True), primary_key=True, default=uuid.uuid4)
    board_id: Mapped[uuid.UUID] = mapped_column(   # FK column ends with _id
        Uuid(as_uuid=True),
        db.ForeignKey("boards.id", ondelete="CASCADE"),
        nullable=False,
    )
    name: Mapped[str] = mapped_column(String(255), nullable=False)
    position: Mapped[int] = mapped_column(Integer, nullable=False)

    __table_args__ = (
        UniqueConstraint("board_id", "name", name="uq_board_columns_board_id_name"),
        Index("ix_board_columns_board_id", "board_id"),
    )
```

## Migration Safety

### Rule
Every database schema change MUST be version-controlled via a Flask-Migrate/Alembic migration. Autogenerated migrations MUST be reviewed before being applied. `db.create_all()` MUST NOT be used as a migration strategy in production. Potentially destructive changes (dropping columns, changing nullability, renaming columns) MUST include a data preservation step and a rollback plan.

### Rationale
Schema changes without migrations make it impossible to reproduce the database state from source control, block zero-downtime deployments, and risk permanent data loss on destructive operations.

### RevoTask Example
```bash
# Generate migration after model changes
flask db migrate -m "rename position to order on cards"

# Review the generated file in migrations/versions/ before applying
# Then apply:
flask db upgrade
```

```python
# Example migration fragment — safe column rename with data preservation
def upgrade():
    # Step 1: add new column
    op.add_column("cards", sa.Column("order", sa.Float(), nullable=True))
    # Step 2: copy existing data
    op.execute("UPDATE cards SET \"order\" = position")
    # Step 3: enforce NOT NULL after backfill
    op.alter_column("cards", "order", nullable=False)
    # Step 4: drop old column only after verification
    op.drop_column("cards", "position")

def downgrade():
    op.add_column("cards", sa.Column("position", sa.Integer(), nullable=True))
    op.execute('UPDATE cards SET "position" = CAST("order" AS INTEGER)')
    op.alter_column("cards", "position", nullable=False)
    op.drop_column("cards", "order")
```
